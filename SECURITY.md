# Segurança e tratamento de informações

Este repositório contém documentação de um laboratório autoral de simulação offline e exemplos inteiramente sintéticos. O motor ainda não está implementado e o MVP não foi homologado. Requisitos de segurança descritos na especificação não comprovam controles implementados ou testados.

## Escopo admitido

O lote admite documentação própria revisada e exemplos fictícios identificados. Não admite dados pessoais, registros operacionais reais, relatórios de análises externas, inventários de recursos externos ou material de terceiros. Consulte [direitos](RIGHTS.md) e [materiais excluídos](docs/EXCLUDED_MATERIALS.pt-BR.md).

A futura implementação deve preservar o funcionamento offline, a origem sintética das entradas e a separação entre cálculo simulado e ações reais. A especificação não autoriza acesso a contas, execução financeira, custódia ou testes sobre serviços de terceiros.

## Não incluir em commits, issues ou anexos

Não inclua credenciais, cookies, tokens, chaves de API, dados de sessão, parâmetros de autenticação, identificadores de conta, códigos de indicação, endereços vinculados a pessoas, saldos ou históricos pessoais. Também não inclua capturas privadas, HAR, respostas autenticadas, logs brutos, diretórios pessoais, pacotes de sessão ou arquivos externos sem direitos verificados.

Use valores fictícios nos exemplos e identifique-os como sintéticos. Não envie informações privadas a um scanner público para validar este repositório. Uma busca textual sem ocorrências não certifica que todo segredo possível foi identificado.

## Comunicar um problema

Para erro editorial sem informação sensível, uma issue pode descrever o trecho e a correção proposta. Para exposição de informação privada ou problema explorável, não publique os detalhes em uma issue. Use um canal privado do mantenedor; o recurso privado de segurança do GitHub só deve ser utilizado se estiver efetivamente habilitado. Na ausência de um canal verificado, solicite um meio privado sem incluir a informação sensível.

O relato deve minimizar os dados e distinguir o comportamento observado de uma hipótese. Não é necessário explorar um serviço externo para comunicar um problema deste projeto. Este documento não promete prazo de atendimento, recompensa ou autorização para testes de terceiros.

## Revisão de mudanças

Cada mudança pública deve preservar o escopo offline e sintético, os direitos sobre o conteúdo e a exclusão de dados privados. O registro de revisão está em [PUBLICATION_REVIEW.pt-BR.md](docs/PUBLICATION_REVIEW.pt-BR.md). Uma ampliação de escopo deverá ser avaliada na mudança concreta; não está implícita nesta especificação.
